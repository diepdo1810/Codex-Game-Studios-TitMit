# Model selection

Role seniority describes responsibility, not a model guarantee. Use `.codex/model-policy.json` for task policy and capability requirements. The active host/account determines available models and reasoning controls. Follow explicit user choices; otherwise inherit the session unless an authorized invocation and verified capability support an override.

Native Skills require `name` and `description`; a source `model:` alias is not a native Skill model switch. Native roles live in `.codex/agents/*.toml` with `name`, `description` and `developer_instructions`. Optional model fields must match the installed client's schema. Source model metadata in provenance records is attribution, never an execution setting.

Match effort to the task: bounded lookups need less reasoning than implementation; cross-system synthesis and release gates need careful evidence. Never promise savings, context size, independence or a particular model from a role title. Record observed host/model for behavioral execution; unavailable runtime verification remains PENDING.
